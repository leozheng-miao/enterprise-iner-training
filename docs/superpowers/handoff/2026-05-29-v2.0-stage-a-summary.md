## 1. 一句话定位

Stage A 在 v1.0.0 之上引入一层 **LLM 网关抽象**：上层只说"我是 Researcher 角色，帮我调一次模型"，由网关负责**查路由表 → 选供应商 → 选模型 → 调用 → 归一化返回**。4 个供应商（OpenAI / DeepSeek / DashScope / vLLM）**都走 OpenAI 协议**，仅 base-url / api-key / model 不同，故共用一套调用代码。

```
Agent 角色 ─► LLMGateway.chat(role, req, tenantId)
                 │
                 ├─ ModelRouter.resolve(role, tenantId)        ← 读 agent_model_routing（租户覆盖全局 + 5s 缓存）
                 │       └─► ResolvedRoute{ provider, primaryModel, fallbacks, crossEnabled, promptVersion }
                 │
                 └─ 选中对应 ChatService（4 实现之一）
                         └─► Spring AI OpenAiChatModel.call() ─► 大模型 ─► 归一化 ChatResponse
```

## 2. 实现的功能清单（按能力）

### 2.1 LLM 网关抽象层（统一入口）
- **`LLMGateway`**：唯一对上入口，3 个方法
  - `ChatResponse chat(AgentRole role, ChatRequest req, Long tenantId)` —— 按角色路由并调主模型
  - `List<Embedding> embed(EmbedRequest req)` —— 文本向量化
  - `List<RerankItem> rerank(RerankRequest req)` —— 重排
- **归一化 DTO**：`ChatRequest{systemText,userText,vars,modelOverride}`、`ChatResponse{content,model,promptTokens,completionTokens,finishReason}`，屏蔽 Spring AI 内部类型，方便后续替换底层实现。

### 2.2 多供应商支持（4 Provider 复用一套代码）
- 枚举 **`Provider`** = `OPENAI / DEEPSEEK / DASHSCOPE / VLLM`。
- **`AbstractOpenAiChatService`**：把 `ChatRequest` 转 Spring AI `Prompt`、调用、再把响应映射回网关 `ChatResponse`（含 null 容错：result/metadata/usage/content 均防空）。
- 4 个薄子类（`OpenAiChatServiceImpl` / `DeepSeekChatServiceImpl` / `DashScopeChatServiceImpl` / `VllmChatServiceImpl`），各自 `@Qualifier` 注入对应模型 Bean、声明自己的 `provider()`。
- **`OpenAiChatModelFactory`** + **`LLMProviderConfig`**：用 `app.llm.providers.<name>` 配置为每个 Provider 造一个独立 `OpenAiChatModel` Bean。

### 2.3 Agent→Model 路由（解耦核心）
- **`DefaultModelRouter`** 读 `agent_model_routing` 表，按 `(agent_role, active)` 解析当前生效路由：
  - **租户覆盖全局**：同时取 `tenant_id IN (0, 当前租户)`，**租户行（tenant_id>0）优先于全局行（tenant_id=0）**。
  - **5s 内存缓存**：键 `role::tenantId`，TTL 5 秒，`ConcurrentHashMap`，挡住高频查库。
  - **fallback 解析**：把 `same_provider_fallbacks` / `cross_provider_fallbacks` 的 JSON 解析为列表（Stage A 仅解析、不消费；降级逻辑在 Stage B）。
  - **prompt 版本解析**：按 `(agent_role, is_active)` 从全局表 `prompt_template` 取生效版本，按 `version DESC LIMIT 1` 取最新（多行也确定性，不抛异常）。
- 解析结果 **`ResolvedRoute`** 带 `toJson()`，供 Stage B 写 `workflow_node_run.routing_snapshot` 做事后归因。

### 2.4 网关门面分发
- **`DefaultLLMGateway`**：构造时把 4 个 `ChatService` 装进 `EnumMap<Provider,ChatService>`；`chat()` 时按 `ResolvedRoute.provider()` 选实现，**`modelOverride` 优先于 `primaryModel`**，未知 provider 抛 `IllegalStateException`；embed/rerank 直接委托。

### 2.5 Embedding / Rerank 归一化壳（单 Provider 预留）
- **`DashScopeEmbeddingService`** / **`DashScopeRerankService`**：包住既有 `DashScopeEmbeddingClient` / `DashScopeRerankClient`，把结果映射成网关 DTO（`Embedding{index,vector}` / `RerankItem{index,relevanceScore}`），为将来多 Provider 留接口。

### 2.6 默认路由播种（开箱即用）
- **`AgentModelRoutingSeeder`**（`@PostConstruct`）：启动时若 `agent_model_routing` 为空，插入 **7 行默认路由**（7 个角色各一行，全部 `DASHSCOPE / qwen-max / active=1 / tenant_id=0`）；表非空则跳过（**幂等**）。

### 2.7 数据模型扩展（DDL）
`schema-phase8.sql`（手动执行脚本）：
- 新建 **`agent_model_routing`**（路由表，唯一键 `uk_tenant_agent_active`）。
- 新建 **`routing_change_log`**（路由变更审计）。
- 新建 **`alert_webhook_config`** / **`alert_event`**（告警两表，**Stage A 仅建表占位，Entity/Mapper 留 Stage C**）。
- `prompt_template` 加 `agent_role` + 索引 `idx_prompt_agent_active`（该表平台级全局，**无 tenant_id**）。
- `workflow_node_run` 加 `trace_id / span_id / routing_snapshot`（Stage B/C 链路追踪与归因用）。

## 3. 关键设计决策

| 决策 | 说明 | 原因 |
|---|---|---|
| 4 Provider 共用 `OpenAiChatModel` | 仅 base-url/key/model 不同 | 全是 OpenAI 协议，省去 4 套适配 |
| `dashScopeChatModel` 标 `@Primary` | 5 个 `OpenAiChatModel` Bean（4 新 + 1 autoconfig）消歧 | 现有 Agent 注入的 `ChatClient.Builder` 需单候选，沿用 DashScope，不破坏 v1.0.0 启动 |
| `prompt_template` 不加 tenant_id | 路由按 `(agent_role, is_active)` 全局生效 | 该表是平台级全局资产（见 phase4 多租户脚本） |
| 路由 5s 缓存 | 内存 TTL，非分布式 | Stage A 够用；分布式缓存/失效推送留后续 |
| API key 仅环境变量注入 | `${DASHSCOPE_API_KEY:}` 等 | 安全：禁止明文 secret 进 git |
| DB 布尔用 `Integer 0/1`、时间用 epoch-millis `Long` | 团队约定 | 规避 Lombok is- 前缀坑、统一时间表示 |
