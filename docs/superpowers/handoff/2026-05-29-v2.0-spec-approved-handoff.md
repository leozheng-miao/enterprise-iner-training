## 3. 用户与我对齐的关键决策（避免再问）

| 项 | 决定 |
|---|---|
| Provider | DashScope（保留）+ vLLM（保留）+ **OpenAI 官方** + **DeepSeek 官方** |
| 路由维度 | Agent 角色 + Prompt 版本，**两者解耦**（用户明确驳回耦合方案） |
| 路由存储 | 改 `prompt_template` + 新增 `agent_model_routing` + `routing_change_log` |
| Embedding | 单 Provider（DashScope），接口预留，运行时**禁切** |
| Rerank | 多 Provider 接口预留，先单 DashScope |
| Resilience | 同 Provider fallback（默认开）+ 跨 Provider fallback（默认关、Admin 可开）+ Resilience4j retry/CB + 告警系统 |
| Advisor 链 | PromptResolution / Resilience / Trace / TokenUsage **4 件套**（顺序就是这个）；不要 QA/Memory Advisor |
| 上下文模型 | 新增 `WorkflowContext` / `AgentContext`，5 Agent 间传递；**RAG 保持自研**（Hybrid + RRF + Rerank + Citation 不动） |
| OTel | traces + metrics 都做；自研 `workflow_node_run` 表**双写保留**（不替换） |
| 基础设施 | docker-compose 加 Jaeger / Prometheus / Grafana / OTel Collector |

**4 个用户特别强调的设计原则**（不要走回头路）：
1. Prompt 与 Model **必须解耦**——直觉胜过"一行省事"
2. RAG **保留自研**——QuestionAnswerAdvisor 会埋没简历亮点
3. **不要 ChatMemory**——用 WorkflowContext 才贴合 5 Agent 协作场景
4. 告警是一等公民——`alert_event` 表 + Webhook + Admin SSE 推送一并交付

## 6. writing-plans 阶段的注意点

下面是给执行 writing-plans skill 的你的提醒（基于本会话观察到的偏好）：

1. **拆分粒度**：用户接受 2-3 周的工作量，但要分阶段交付。建议至少拆 3 个阶段：
   - Stage A：DDL + LLMGateway + 4 个 ChatService（地基）
   - Stage B：Advisor 4 件套 + WorkflowContext + 5 Agent 接入
   - Stage C：OTel + Grafana + 告警 + 前端 Admin
2. **测试与实现并行写**：用户接受 v1.0.0 团队约定（无 MockMvc Controller 测试，只 Service 单测）。延续该约定，不要给 Controller 写 MockMvc。
3. **DDL 单文件**：所有 4 张新表 + 改表统一进 `src/main/resources/db/schema-phase8.sql`，用 `IF NOT EXISTS` 可重入（沿用 v1.0.0 模式）。
4. **不破坏向前兼容**：v1.0.0 的 Admin 页面 API 不能改字段。新字段只能加不能删。前端 Admin Stats / Workflow / Judge 三页本次不动。
5. **schema 兼容陷阱（v1.0.0 §11 已踩过）**：
   - Lombok `boolean` 字段 Jackson 序列化丢 `is` 前缀
   - 时间字段一律用 `xxxAt` (epoch millis Long)
   - 不要混 `createTime` / `createdAt`
6. **fallback 路径埋点**（spec §5.2 最后那个 ⚠️）必须写单测，否则 Trace / Token 会在跨 model fallback 时丢数。
7. **Spring AI 1.0.0 + Resilience4j retry + OTel context** 三者集成有已知坑（spec §10 风险表第 6 条），单测必须覆盖"retry 后 child span 挂载正确"。
